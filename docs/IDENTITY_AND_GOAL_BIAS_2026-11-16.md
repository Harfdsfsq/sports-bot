# Исправления сопоставления матчей и ошибки голов — 16 ноября 2026

## Проверенные проблемы

В артефакте run-bot 43820786355 линия и контекст разделялись между вариантами названий одного матча: Inhulets — Probiy Horodenka / FC Ingulets Petrove — Probiy Gorodenka; UCSA — Polissya II / FC Ucsa Tarasivka — FC Polissya Zhytomyr 2; Chernihiv / FC Chernigiv. Ответ Odds API находился, но проверка fixture_identity_mismatch отклоняла его для короткого названия SStats.

Новая консервативная стратегия v1 достигла 282 калибровочных матчей, однако на проверочной части уступила рынку. Коэффициент отклонения от рынка alpha=0. Значит, сам факт накопления 160 матчей не доказывает преимущество и не разрешает ставки. Основная контрольная модель остаётся отрицательной.

## Сопоставление: только проверенные случаи

Добавлен config/reviewed_fixture_aliases.json и отдельная функция scoped_fixture_alias_match. Разрешены перечисленные полные варианты названий в украинской Persha Liga сезонов 2026/2027. Проверяются оба соперника в исходной ориентации, точное время с явным часовым поясом и одинаковый возрастной/женский/резервный состав. Страна должна следовать из явно украинского названия лиги либо сохранённой SStats-квитанции с соответствующим ID. Неверная страна, другой турнир, другой соперник или другое время не проходят.

Сверены первичные материалы ПФЛ с названиями и городами клубов:
- https://pfl.ua/news/matchday-persha-liha-vosmyy-tur-anons-matchiv-nedili
- https://fc.if.ua/matches/1928/ (публичный поисковый результат; прямой просмотр вернул 403)

Точные варианты написания между провайдерами также сохранены в квитанциях указанного run. Эти соответствия не становятся глобальными алиасами истории и не переписывают canonical team keys.

Реестр объединяет только доказанные точные дубликаты, сохраняет provider IDs и исходную метаинформацию SStats. Конфликтующие ID, два подтверждения публикации или разные kickoff блокируют объединение. Сохранённые evidence не получают новые timestamps; обычные проверки давности и допуска контекста продолжают действовать. История SStats остаётся привязана к оригинальному team ID и имени его квитанции, даже если сохранено название Odds API.

Проверка квитанций Odds API и SStats использует тот же ограниченный механизм. Пересмотрены правила повторной попытки: ранее отклонённая линия с исправленной и теперь проверяемой идентичностью может быть запрошена один раз до истечения старого empty-cooldown. Отрицательный ответ новой версии снова включает обычный cooldown. Дополнительных источников API и новых квот нет.

Результат повторной обработки снимка: 146 записей реестра стали 143. Это удаление трёх дубликатов, а не потеря матчей. Оно не доказывает рост свежего покрытия без следующего сбора котировок: просроченная линия по-прежнему просрочена. Время конфликтующих матчей не угадывается.

## Новая независимая версия оценки голов

conservative-totals-v2 дополнительно оценивает систематическое отклонение shrunk-ожидаемых голов от реальных голов. Для поправки используются все подходящие исходные прогнозы, а не только выбранные ставки или поражения.

Коэффициент обучается только на ранней обучающей части. Вес давности имеет период полураспада 90 дней; поправка стягивается к 1 с приором 60 матчей и ограничивается диапазоном 0.8–1.25. На следующую проверочную часть переносятся уже зафиксированные коэффициенты. Цели проверочной части не участвуют ни в этой поправке, ни в обучении последующей логистической калибровки.

Скорректированная Poisson-вероятность для тотала 2.5 смешивается поровну с прежней средней shrunk/overdispersed-вероятностью. Затем применяется прежняя осторожная поправка относительно рынка. Сохраняются требования: победить рынок одновременно по Brier и log loss на отложенном периоде, иметь свежую парную линию двух букмекеров, достаточную историю команд, согласованность оценок и положительную доходность после стресс-снижения вероятности. Пороги не снижены.

На последнем артефакте взвешенные средние в обучении: ожидалось 2.778 гола, фактически 2.954. Обученная поправка 1.04835. Проверочный период (87 матчей) всё ещё даёт market_not_beaten: Brier 0.25804 против рыночных 0.25565. Поэтому публикации/выбор ставок не разрешаются. Исправление не считается доказанным улучшением прибыли.
