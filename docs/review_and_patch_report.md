# Проверка sports-bot: лог, сообщение и фикс

## Что нашёл по логам и debug-run

Разбор делался по:
- `.data/debug-last-run.json`
- `.data/sheet-bet-ledger.csv`
- логам из `logs_65277356079.zip`
- последнему telegram-сообщению из run-артефактов

### 1) В последнем прогоне бот почти не доводил до публикации рынки кроме 1X2

По логу последнего запуска:
- `candidates_before_quality = 2`
- `candidates_publishable = 1`
- в Telegram ушла 1 ставка
- в debug было 102 сырых модельных записи, из них:
  - `h2h`: 36
  - `totals`: 66
  - `spreads`: в финальный debug-пул практически не попадали

Ключевые причины отбраковки:
- `missing_context_totals = 33`
- `missing_context_spreads = 33`
- `market_derived_signal_guard_totals = 104`
- `publish_books_guard = 21`

Итог: рынки тоталов/фор логически поддерживались моделью, но до финального списка почти не доходили из-за плохого контекста и неполного парсинга офферов.

### 2) Критичный баг в API-Football контексте

В `api_football` бот брал `predictions.goals.home/away` как ожидаемые голы.
Но в реальных ответах из debug были значения вроде:
- `home = -2.5`
- `away = -2.5`
- `under_over = -3.5`

Это не xG, а явно другой тип линии/подсказки. В итоге:
- в контекст попадали некорректные отрицательные expected goals
- тоталы и форы часто отваливались как `missing_context_*`
- часть оценок строилась на повреждённом контексте

### 3) Критичный баг в парсинге фор из odds_api_io

В `OddsApiIoProvider` для рынка `spreads` не проставлялся `team_side`.
Но модель строит форы только если есть:
- `point`
- `team_side in {'home', 'away'}`

То есть офферы по форам приходили, но дальше модель их почти не могла использовать как положено.

### 4) Парсер odds_api_io был слишком узким по рынкам

Из основного источника не разбирались или были искусственно отрезаны:
- `btts`
- `double chance`
- `draw no bet`
- `team totals`

Из-за этого бот структурно терял часть рынков ещё до модели.

### 5) В тексте сообщения были слабые места

Для новых рынков сообщение было подготовлено не до конца:
- `teamTotals` могли бы выводиться неясно, без указания команды
- `doubleChance` мог бы печататься сырой строкой вместо `1X / X2 / 12`
- в объяснении фраза про цену «ниже fair-цены» звучала так, будто ставку уже не стоит брать, хотя модель всё ещё оставляла положительный перевес

## Что изменено

### 1) Исправлен расчёт контекста в `app/providers/api_football.py`

Сделано:
- отрицательные и аномальные `predictions.goals.*` больше не считаются xG
- если явного корректного xG нет, expected goals теперь собираются из:
  - средних голов за/против
  - last 5 form
  - вероятностей home/draw/away
  - подсказки `under_over`
- в details сохраняется источник xG (`predictions_goals` или `team_stats_blend`)
- в контекст добавлены полезные attack/form/defense показатели

Эффект:
- тоталы и форы снова получают валидный числовой контекст
- отрицательные expected goals больше не протекают в модель

### 2) Исправлен парсинг markets в `app/providers/odds_api_io.py`

Сделано:
- для `spreads` теперь ставится `team_side`
- добавлен разбор рынков:
  - `btts`
  - `doubleChance`
  - `dnb`
  - `teamTotals`
- добавлены нормализаторы для selection и line
- для away-side форы корректно нормализуется знак линии

Эффект:
- модель теперь реально может строить кандидатов не только по 1X2 и totals, но и по форам, BTTS, DNB, double chance, team totals

### 3) Добавлена санитарная проверка expected goals в `app/services/runner.py`

Сделано:
- при blending контекстов значения expected goals проходят фильтр
- отбрасываются `None`, `NaN`, отрицательные и аномальные значения вне разумного диапазона

Эффект:
- ensemble-контекст больше не заражается мусорными xG из одного источника

### 4) Исправлена нормализация double chance в `app/services/model.py`

Сделано:
- `1X` -> `home_draw`
- `X2` -> `away_draw`
- `12` -> `home_away`

Эффект:
- модель и market-key логика согласованно понимают double chance

### 5) Улучшен текст Telegram в `app/services/telegram.py`

Сделано:
- `teamTotals` теперь можно показать с привязкой к команде (`Home Team: Больше`)
- `doubleChance` нормализуется в короткий вид `1X / X2 / 12`
- фраза про просевшую цену стала менее противоречивой

## Быстрые проверки после правки

### Синтаксис
Успешно проходит:
- `python -m py_compile app/providers/odds_api_io.py`
- `python -m py_compile app/providers/api_football.py`
- `python -m py_compile app/services/runner.py`
- `python -m py_compile app/services/model.py`
- `python -m py_compile app/services/telegram.py`

### Sanity-check 1: API-Football
На реальном sample из debug, где раньше приходило `goals.home = -2.5`, после фикса контекст строится так:
- `expected_home ≈ 1.24`
- `expected_away ≈ 1.29`
- источник: `team_stats_blend`

То есть отрицательные xG больше не используются.

### Sanity-check 2: odds parser
На искусственном payload после фикса успешно собираются офферы по:
- spreads
- totals
- btts
- doubleChance
- dnb
- teamTotals

И у spreads/teamTotals теперь есть корректный `team_side`.

## Что по качеству прогнозов

Честный вывод: **оценить качество модели статистически пока нельзя**.

По текущему quality summary:
- `total_tracked_bets = 7`
- `settled_binary_bets = 1`
- `bets_published = 5`
- `bets_settled = 1`

То есть выборка слишком маленькая для выводов по ROI / hit rate.

Сейчас можно уверенно сказать только это:
- логика отбора была структурно перекошена в сторону 1X2
- тоталы и форы недополучали шансы не потому, что модель их не умеет, а потому что ломались на парсинге и контексте

## Что ожидать после фикса

После следующего реального запуска бот должен:
- чаще собирать валидные кандидаты по totals и spreads
- начать нормально подтягивать team totals / BTTS / DNB / double chance
- показывать их в сообщении без двусмысленного текста
- меньше терять рынки на стадии `missing_context_*`

При этом бот всё равно не обязан публиковать все типы ставок в каждом прогоне:
- остаётся ограничение «не больше одной рекомендации на матч»
- остаются edge / EV / quality-фильтры
- если лучший сигнал по матчу — исход, бот всё равно выберет исход

Но теперь другие рынки хотя бы реально участвуют в конкурсе, а не отваливаются раньше времени.
