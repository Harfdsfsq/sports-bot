# Расширение покрытия — 12 ноября 2026

Цель изменения — собирать проверяемые данные по всему предстоящему инвентарю,
сохраняя отдельное четырёхчасовое окно публикации. Получение данных за день,
свежая готовность ближайших матчей и независимое покрытие «2+» теперь показаны
отдельно. Процент 90–95% этим коммитом не объявляется достигнутым.

## Что изменено

### Пакетные котировки PARI

`/Pari/matches?includeOdds=true` возвращает текущие цены сразу для страницы
матчей. Реальный публичный ответ проверен: исходы имеют компактный формат
`{id, value}`, без названий. Их расшифровка загружается из официального
`/Pari/odds/market-types`, кешируется на сутки и восстанавливается при повреждении
кеша. Поддерживаются только полные футбольные рынки 1X2, тоталов, азиатских фор
и обе забьют. Таймы, угловые, карточки и неизвестные/противоречивые ID исключены.

Пакетный ответ больше не ограничен восемью матчами. Детальный запрос остаётся
резервом при отсутствии пригодных пакетных цен. Перед публикацией цена всегда
заново подтверждается детальным ответом; резерв четырёх запросов сохранён.
Все запросы по-прежнему проходят общий ограничитель SStats.

Названия вроде `Alianza` / `Alianza San Salvador` связываются не произвольным
ослаблением сравнения текста, а явными соответствиями ID двух команд. При этом
проверяются исходный матч SStats, время, составы команд и отсутствие конфликта
ID матча. Одинаковые названия не отменяют конфликт явных идентификаторов.

### Контексты Bzzoiro

В v2 `/predictions/` границы имеют формат date-time. Вместо одинаковых дат
без времени теперь передаётся непустой UTC-интервал до последнего целевого матча
и `status=upcoming`. Ответ сопоставляется со всем списком до 300 матчей, а не
только первыми восемью. Лимит восьми сохраняется для дополнительных запросов
сведений о событии, отдельно от бесплатного сопоставления уже полученных прогнозов.
Лимиты запросов, срок выполнения, проверка времени/команд и свежести остаются.

### История и таблицы SStats

- Инвентарь сохраняет команды и их ID из точного ответа SStats. Сам ID не
  превращается в спортивный контекст. Новая ревизия инвентаря — 4 — заставляет
  один раз обновить старый снимок с отсутствовавшими полями.
- Учтён фактический тип `dateUtc`: Unix timestamp в секундах, а не ISO-строка.
- Будущие матчи с подтверждёнными ID позволяют переиспользовать проверенные
  результаты из архива. Время старого получения сохраняется; новый запрос по
  другим командам не делает целиком архивную форму «свежей».
- Прицельная история расширена до 100 матчей, максимум 12 запросов и 45 секунд
  в настроенном профиле. Действуют общий бюджет, пагинация, проверки результатов,
  ID, возрастных/резервных составов и отсутствия будущих результатов.
- Добавлены таблицы `/Games/season-table` по подтверждённым лиге и году: до четырёх
  запросов за проход, кеш шесть часов. Обе команды проверяются по ID. Таблица
  дополняет валидную форму, включая кешированную, без сброса её времени получения.
  Новый независимый контекст или вымышленные xG из таблицы не создаются.

### Очередь и отчёт

Горизонт сбора — 24 часа; фоновая очередь может обработать до 300 матчей,
включая до 300 записей следующего дня. Реальные женские, молодёжные и нижние
дивизионы разрешены для сбора. Симуляции и неизвестные турниры исключены.
Это расширение инвентаря, а не разрешение публикации слабых прогнозов.

Добавлены отдельные показатели:

- `collected_ready`: оба вида данных получены за календарный день;
- `future_matches/line/context/ready`: свежие данные всех предстоящих матчей;
- `near_two_book_lines`: два букмекера на одной стороне одного рынка/тотала;
- `near_two_context_sources`: два допущенных спортивных провайдера;
- `near_two_book_and_context`: оба предыдущих условия.

Погода по-прежнему требует подтверждённого местоположения. Отсутствующие
стадионы, таблицы или составы не заменяются догадками. 300 — целевой размер и
предел инвентаря, а не доказательство наличия 300 подходящих матчей каждый день.

## Проверка

- Основной изолированный набор: **569 passed**.
- Focused Alpha: **81 passed**.
- Ruff изменённых модулей и новых тестов: passed. Mypy smoke всех 42 изменённых
  Python-модулей с `--follow-imports=silent`: passed.
- Полный локальный изолированный pytest: **97 failed, 983 passed**. Это отдельные
  неустранённые ошибки общего набора; полный CI не объявляется зелёным.
- Тест с 120 матчами подтверждает пакетную обработку без запроса на каждый матч.
- На публичных реальных ответах, отдельно от production-запуска, PARI дал 1748
  пригодных полных котировок для 56 из 91 выбранного предстоящего матча. Это
  **один букмекер**, а не суммарный охват всех API и не итог всего рабочего дня.
- В отдельной проверке истории тех же источников: 1273 завершённых игры за три
  страницы, 61 контекст с минимальной формой, из них 35 с шестью играми каждой
  команды. Эти снимки показывают доступность данных, не прибыльность модели.

Окончательный процент рабочего охвата после изменения должен быть измерен по
артефакту нового обычного запуска. Данные Bzzoiro с ключом и объединение всех
букмекеров в этой публичной проверке не проверялись.

Политика публикации A-only и dry-run не изменена. Из-за новой версии сбора и
изменения контрольного хеша объявлен `opponent-forward-v3`: предыдущие объявления
протокола архивируются, исходные прогнозы и результаты остаются в журнале.
Старые результаты не переносятся в новую проверку как заранее доказанный плюс.
