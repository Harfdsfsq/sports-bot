# API: бесплатные лимиты и ежедневная маршрутизация

Проверено по публичным первичным источникам 7 октября 2026 года. Документ относится к `PUBLICATION_PROFILE=daily_quality` и workflow `run-bot-rules`. Личный тариф, наличие GitHub Secrets и доступ к конкретным соревнованиям подтверждаются ответами следующего запуска, а не публичной страницей цены.

## Единая система запросов

1. Инвентарь строится для дня MSK с постоянными ID матча и привязками ID каждого поставщика. У Bzzoiro запрашиваются страницы по 200 и предыдущая UTC-дата: вечер UTC относится уже к следующему дню MSK. Недоступные реальные матчи не создаются ради числа 300.
2. Каждый запуск сначала обрабатывает окно 30 минут — 4 часа, затем до 60 матчей следующего окна и до 60 матчей дальнейшего инвентаря. Целевой предел провайдера — 300 матчей вместо прежних 80.
3. Линии запрашиваются пакетами по ID источника. Близкая линия живёт в кеше 15 минут; линия следующего окна — 2 часа, дальняя — 4 часа. При переходе матча в ближайшее окно старый кеш перестаёт считаться актуальным. Контекст использует отдельный существующий кеш, привязанный к матчу.
4. Все активные HTTP-клиенты инвентаря, обогащения, погоды и расчёта результата проходят через `BudgetedAsyncClient`. Перед реальным HTTP резервируется попытка; ошибка сети тоже считается расходом. Недоступный источник не блокирует остальные.
5. Бюджет сохраняется в `.data/daily_quality/api-budget.json` отдельно от основного кеша workflow. Dry-run и рабочие запуски одной ветки делят этот бюджет; запуски workflow выполняются последовательно. GitHub ограничивает доступность кешей между ветками: общий префикс не гарантирует межветочный учёт. Файл защищён блокировкой и атомарной записью; повреждённый файл не сбрасывает квоту автоматически. Ключи и URL запросов не сохраняются, используются отпечатки ключей.
6. Часовой лимит считается скользящим; локальные дневные/месячные корзины — UTC. Серверные заголовки Bzzoiro и odds-api.io учитывают расход вне этого workflow и имеют приоритет. `Retry-After`, 401 и 429 включают ожидание; 402/403 закрывают конкретный endpoint, не весь спортивный API.
7. После обогащения работают существующие проверки цены, вероятности, xG, дублей, A/B и риска. Один контекст и одна текущая линия остаются базовым контрактом; дополнительные источники усиливают проверку. Порог качества не снижается ради количества ставок.

Полезный расход важнее пустого исчерпания квоты. Для odds-api.io полный пакетный проход 300 матчей занимает примерно 30 запросов на аккаунт плюс метаданные; 12 таких проходов помещаются в 500/день при условии доступности линий и бюджета остальных операций. Реальные запросы ограничены также deadline и локальными лимитами каждого адаптера. У Bzzoiro широкие страницы эффективнее повторных одиночных запросов. Повторно скачивать свежий кеш только ради расхода лимита система не должна.

## Второй аккаунт odds-api.io

В GitHub Secrets нужен `ODDS_API_IO_KEY_2` либо прежнее имя `ODDS_API_IO_KEY2`. Workflow передаёт оба варианта в одну переменную. Конфигурация больше не содержит пустых строк ключей и не затирает secrets; загрузчик отклоняет попытку положить credentials в публичный профиль.

Два разных ключа создают два независимых бюджета. Одинаковые ключи дедуплицируются. Второй аккаунт использует выбранных **на нём** букмекеров: чтение `/bookmakers/selected` кешируется на 6 часов; при временной ошибке метаданных используются настроенные Bet365/Unibet, доступность которых ещё должен подтвердить сервер. Betfair Exchange/Sbobet больше не навязываются бесплатному аккаунту. Настройки букмекеров у поставщика скрипт не меняет.

Ошибка или исчерпание квоты аккаунта 1 не прекращает получение линии аккаунтом 2. В Telegram показывается состояние каждого аккаунта: линии получены, кеш, квота, ошибка доступа или отсутствие ключа. Две учётные записи одного поставщика не считаются двумя независимыми API.

## Проверка после ручного запуска

- Оба аккаунта видны в `source_stats.odds_api_io.configured_accounts`; в `accounts` указаны запросы, доступные букмекеры и найденные линии.
- `api_budget` содержит расход и блокировки без credentials; `api-budget.json` сохраняется между рабочим и dry-run запуском.
- В инвентаре и ближайшем окне отдельно видны текущая линия, контекст, форма, таблица и погода. Нулевое покрытие остаётся честным: квота не исправляет отсутствующий venue, сезон или неподдерживаемую лигу.
- A: качество 78+, confidence 70+, EV 5%+, edge 3 п.п.; B: 65+, 60+, 3%+, 2 п.п. Публикация минимум за 30 минут, окно 4 часа, максимум 5 в день. Это оценки модели, не подтверждённая проходимость.

Лимиты можно переопределять через `API_BUDGET_<PROVIDER>_RPM/HOUR/DAY/MONTH` только после сверки действующего тарифа. Для odds поддерживаются также отдельные `ODDS_API_IO_ACCOUNT1/2_HOURLY_LIMIT` и `..._DAILY_LIMIT`. Другие workflows и внешние клиенты не разделяют локальный файл; их расход учитывается лишь там, где API возвращает серверные счётчики. GitHub Actions cache может быть удалён/вытеснен, поэтому это локальный учёт, а не полная выписка аккаунта поставщика. Никакие подписки или платные endpoints автоматически не активируются.

С 7 октября профиль аккаунта 2 настроен на `1xbet,Betano`, аккаунта 1 — на Bet365/Unibet. При изменении настройки профиля старый кеш выбранных букмекеров перечитывается до запросов линии. Блокировка 403 привязана к endpoint и набору запрошенных букмекеров; новая разрешённая подборка не ждёт блокировку прежней платной подборки. Дневные и часовые счётчики при этом сохраняются.
