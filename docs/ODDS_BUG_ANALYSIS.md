# Что ломается

По свежему кейсу у бота одновременно появились:

- опубликованный `ТБ(2.5)` с коэффициентом `2.28`
- консенсусная вероятность `59.2%`

Эти цифры не согласуются между собой: `59.2%` соответствует fair odds около `1.69`, а не `2.28`.

## Наиболее вероятный класс ошибки

В `app/services/model.py` тоталы сначала группируются по `(selection, point)`, затем `point` переписывается через `_normalize_supported_line(...)`, а дальше в расчёт кандидата идут:

- `offers=bucket` — исходный bucket офферов по сырой линии
- `point=normalized_point` — уже нормализованная линия
- `market_prob = self._fair_market_probability_totals(bucket, offers, selection, point)` — консенсус считается уже с использованием нормализованного `point`

Из-за этого возможен класс багов, где:

1. коэффициент остаётся от сырого offer/bucket
2. линия в Telegram уже нормализована
3. консенсусная вероятность считается по другой линии

Итог: бот может показать `ТБ(2.5) @ 2.28`, хотя реальный `2.28` относился к другой линии.

## Что делать сразу

1. Снизить `LINE_SUPPORT_TOLERANCE` до `0.02`.
2. Ограничить поддерживаемые тотал-линии стандартным набором.
3. Перед публикацией прогонять `scripts/audit_odds_sanity.py`.
4. Любой totals-сигнал с аномальным расхождением между `odds` и `consensus fair odds` отправлять в reject/shadow.

## Что надо править в коде

В `model.py` нужна жёсткая инварианта:

- если линия нормализована, то и bucket должен быть пересобран по этой же линии;
- если bucket остаётся сырым, то и публикация должна использовать сырой point;
- `selected_offer.price`, `display point`, `market_prob` должны относиться к одной и той же линии.

До этой правки totals-публикацию надо держать консервативной.
