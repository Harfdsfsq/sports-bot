# Проверка исправленного sports-bot

Ветка: `fix/manual-prediction-pipeline`. Запускать существующий workflow
`run-bot-rules`, выбрав эту ветку в **Run workflow → Use workflow from**.
Изменения main и автоматические запуски main этим не переключаются.

## Первый запуск

1. Откройте Actions → run-bot-rules → Run workflow.
2. Выберите `fix/manual-prediction-pipeline`.
3. Оставьте `dry_run=true`, `max_picks=2`, `use_secondary_odds_account=false`.
4. Дождитесь завершения и скачайте artifact `run-bot-rules-<run_id>`.
5. Посмотрите `latest-manual-run-report.txt`, JSON с тем же именем,
   `latest-run-bot-rules.log`, `latest-daily-coverage-plan.json` и
   `latest-controlled-fallback-report.json`, если резерв запускался.

Dry run выполняет реальные запросы к провайдерам и расходует их квоты, но
не отправляет прогнозы или отчёты Telegram. Токены Telegram удаляются из
окружения процессов pipeline и fallback. Служебный отправщик учитывает dry run.

## Проверка Telegram

Повторите запуск с `dry_run=false`. Нужны существующие repository secrets:
`TELEGRAM_BOT_TOKEN` (или `TELEGRAM_TOKEN`), `TELEGRAM_CHAT_ID`,
`ODDS_API_IO_KEY`, `BZZOIRO_API_KEY`, `SSTATS_API_KEY`.
Не вставляйте ключи в inputs или логи. Бот должен иметь доступ к выбранному чату.
Отчёт текущего запуска должен прийти даже при отсутствии подходящей ставки;
ошибка отправки отчёта завершает job с ошибкой.

Для накопления проверки движения линии сделайте ещё один запуск того же
режима через 8–15 минут. Состояние dry/live разделено, поэтому первая live
проверка начинает собственную историю линий. Исходный guard может ждать
следующего штатного cron либо разрешить финальную проверку, если до матча
больше нет полезного cron. Ноль прогнозов при отрицательном value или
неподтверждённой линии является корректным результатом.

На время live проверки избегайте одновременной публикации из main:
дедупликация разных веток разделена, поэтому возможны одинаковые прогнозы.

## Что изменено

- Отключение Focused Alpha отключает также обрезание входа модели.
- План от другого GitHub run не применяется к текущему.
- В явном `rules_ab` B-tier допускает 1 источник odds + 2 букмекера +
  1 контекст. A-tier сохраняет 2 odds + 2 букмекера + 2 контекста.
  Другие профили сохраняют строгий минимум; запрет B-tier учитывается.
- Контекст не считается ценовым подтверждением. Value, historical quality,
  актуальность цены, время начала и движение линии остаются обязательными.
- Начальный тест ограничен рынком totals и максимум двумя прогнозами.
  Резерв не запускается после отправки основной подборки.
- Второй аккаунт odds-api.io отключён по умолчанию: в исследованных запусках
  его букмекеры возвращали HTTP 403. Включайте отдельным input только после
  проверки тарифных прав; этот input не исправляет тариф провайдера.
- Sportlogic отключён в тестовом workflow. Остальные провайдеры сохраняют
  ограниченные бюджеты и существующий маршрутизатор запросов.
- Кэш разделён по ветке и режиму; отчёты из репозитория удаляются до запуска.
  Отправщик отчёта читает свежие результаты, не выполняет дополнительный сбор
  данных и не принимает служебные сообщения за отправленные прогнозы.
- Устранена синтаксическая ошибка в `send_clean_detailed_run_report.py`,
  мешавшая общей компиляционной проверке.
- Исправлен импорт старого entrypoint отчёта v10. Новый workflow использует
  отдельный read-only отчёт, не старую цепочку v5/v13.

## Как оценивать результат

Сверьте матчи модели, матчи с линиями, контексты, кандидатов до/после quality
и `published_to_telegram`. Если линия/контекст по-прежнему почти отсутствует,
проверяйте HTTP 403/429 и mapping в логе: исправление отбора само по себе
не создаёт отсутствующие данные. Изучайте причины отказа в подробных JSON.
Сводка считает прогнозы основного pipeline и резерва отдельно.

Высокий процент проходимости этой веткой не доказан. До регулярных ставок
нужны журнал всех прогнозов с исходами, ROI, коэффициентами и калибровкой
вероятностей на данных, не использованных для настройки. Не ослабляйте
historical quality или value ради обязательного количества публикаций.

## Регулярная эксплуатация после проверки

Ветка предназначена для ручной проверки. GitHub schedule работает с default
branch, поэтому создание этой ветки не включает новое расписание.
`production-schedule` в ветке передаёт явный live режим и ref для будущего
перехода. До слияния отдельно устраните дублирующее расписание legacy
`run-bot.yml`, проверьте квоты провайдеров и результаты live испытаний.
Слияние и запуск Actions в рамках этой правки не выполнялись.

## Проверки кода

Новые регрессионные тесты проверяют выбор профиля, отключение Focused Alpha,
свежесть плана/сводки, блокировку лишнего резерва и ошибки отчёта Telegram.
Реальные ключи и отправка Telegram локально не использовались.
В baseline уже падают тест legacy v8 отчёта и один тест cron/line movement;
они не являются подтверждением работоспособности новой ветки.
