## Исправления

- William Hill корректно нормализуется при построении пар Over/Under.
  Исследование учитывает реальные котировки Odds-api.io, SStats PARI и TheOddsAPI;
  одинаковый букмекер из разных API считается один раз.
- Проверенные идентификаторы PARI связываются с матчами. Дубли с разными написаниями
  объединяются только при совместимых составах команд, точном времени и отсутствии
  конфликтующих ID. Сохранённые ссылки не позволяют дублям появляться при следующем
  чтении инвентаря. Сам ID не создаёт линию или контекст.
- PARI может независимо собирать цену в последние 30 минут до начала. Отказ
  основного провайдера не отменяет эту попытку. Устаревшие цены отбрасываются;
  время получения цены сохраняется без подмены временем расчёта.
- `price_watch_only` использует тот же paper/live cache, что и выбранный
  `dry_run`. Раньше тестовый режим мог читать live cache.
- Для перспективной модели `opponent` фиксируется новая, заранее объявленная
  выборка. Старые результаты исключаются. Код и правила имеют контрольный хеш;
  изменение модели блокирует прежнее подтверждение, а не переносит его молча.
- Готовность проверяется по новым результатам, вероятностям относительно рынка,
  ценам того же букмекера перед стартом и полноте расчёта исходов. Положительный
  результат исследовательской модели не разрешает публикацию другой модели.
- Для будущего допуска добавлены пределы: 0,25% банка на прогноз, один за запуск,
  два в день, остановка при просадке 5% от максимума банка. Допуск повторно
  проверяется непосредственно перед отправкой. B-tier остаётся наблюдением.
- Добавлена отдельная проверка основного контура в CI; исправлены ошибки Ruff
  Focused Alpha. В общем CI исправлен шаблон, пропускавший Python-файлы; ошибки
  общего набора не скрываются.

## Что нужно до небольшого пилота

Политика находится в `config/prospective_validation.json`: минимум 200 рассчитанных
ставок, 300 парных наблюдений, 30 игровых дней, 50 сопоставимых цен перед стартом.
Нижняя граница 95% интервала ROI должна быть выше нуля, верхняя граница разницы
Brier относительно рынка — ниже нуля, среднее преимущество цены — положительным,
доля просроченных нерассчитанных исходов — не выше 5%.

Это инженерные критерии допуска, а не гарантия заработка. Они могут не выполниться.
Текущий протокол проверяет `opponent`; для перехода потребуется отдельно внедрить
и проверить именно эту модель в публикации. Изменение `dry_run` само по себе
такого перехода не выполняет. На копии последнего артефакта новый протокол даёт
`cohort=0`, `status=collecting`, `live_ready=false` — старые выигрыши не засчитаны.

## Следующий запуск

Обычный двухчасовой запуск оставить на `fix/coverage-integrity-a-only`,
`dry_run=true`, `price_watch_only=false`. После первого запуска проверить
`latest-prospective-validation.json`, сбор PARI и полноту результатов; отчёт
Telegram показывает прогресс проверки, но не разрешает ставки автоматически.

Для цен перед стартом создать **вторую** задачу cron-job.org каждые 30 минут:

```text
POST https://api.github.com/repos/Harfdsfsq/sports-bot/actions/workflows/run-bot.yml/dispatches
Accept: application/vnd.github+json
Authorization: Bearer YOUR_GITHUB_TOKEN
Content-Type: application/json
```

```json
{"ref":"fix/coverage-integrity-a-only","inputs":{"dry_run":true,"price_watch_only":true,"max_picks":"1"}}
```

Токен должен иметь Actions: write для этого репозитория. Не вставлять токены в
репозиторий. Задача собирает только цены отслеживаемых матчей и не отправляет
прогнозы. Внешняя задача этим коммитом не создана. Без неё двухчасовая частота
оставляет пропуски в 45-минутном окне перед матчами. Квоты API и ограничение
числа обрабатываемых матчей всё равно не позволяют обещать полный охват.

После этого исправлены:

- Несуществующий test node в Focused Alpha: workflow теперь запускает существующий
  тест запрета неподтверждённой замены букмекеров. Все 81 тест этого набора проходят.
- Отсутствующая функция чтения JSON для v14 и его вход через отсутствующую цепочку
