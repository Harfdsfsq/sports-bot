# Candidate pool widening fix

## Что исправляет

Последний запуск уже не падал и не имел проблемы с переводом. Проблема стала другой:

- приложение видит матчи и офферы;
- но до `controlled fallback` доходит только 1 кандидат;
- единственный кандидат имеет отрицательный контрольный EV;
- поэтому публиковать его нельзя.

Значит нужно расширить входной пул кандидатов, а не отключать защиту от отрицательного EV.

## Главный принцип

Внутреннее приложение теперь работает как генератор кандидатов и диагностики.
Telegram-публикацию делает только внешний скрипт `scripts/publish_controlled_fallback.py`.

Поэтому thresholds до quality можно сделать мягче, чтобы получить больше near-miss кандидатов. Финальный gate всё равно запрещает:

- отрицательный EV;
- отрицательный edge;
- реальные дубли;
- слишком высокий коэффициент;
- неподдерживаемые рынки.

## Что меняется

Обновлены:

- `config/balanced_output.env`
- `config/conservative_passability.env`

В balanced-профиле:

- расширен candidate supply;
- включён более широкий `market_derived`;
- снижены ранние пороги `MIN_EV_PCT`, `MIN_EDGE_PCT`, `MIN_MODEL_CONFIDENCE`;
- увеличено сохранение shadow-кандидатов;
- controlled fallback остаётся строгим на финальном шаге.

## Как применять

1. Распаковать архив в корень репозитория.
2. Проверить diff в GitHub Desktop.
3. Commit + push.
4. Запустить обычный workflow `Run bot`.
5. Выбрать profile `balanced`.
6. После запуска прислать `run-bot-current`.

## Ожидаемый результат

В `controlled-fallback-report.json` число `candidates_seen` должно вырасти примерно с 1 до 10–40.

Если среди них есть ставка с положительным контрольным EV и edge, бот опубликует 1 контролируемый прогноз.
Если таких нет, бот корректно отправит no-pick отчёт.
