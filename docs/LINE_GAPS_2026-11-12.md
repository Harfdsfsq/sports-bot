## Implemented repairs

1. Record only actual quote-request targets (or completed discovery misses).
   Fixtures omitted by the request cap or incomplete discovery no longer acquire
   an invented empty-result cooldown. They stay eligible for the next run.
2. Keep per-event, per-account outcomes: not queried, absent event in response,
   empty bookmaker data, no parseable supported full-match market, failed request,
   or rejected fixture identity/status. A malformed HTTP-200 response is an
   error, not evidence of absent prices.
3. Before parsing daily quotes, verify event ID, pending status, both teams in
   home/away order and kickoff within 15 minutes. An event ID alone cannot turn
   a live, reversed or changed fixture response into a prematch quote.
4. For successful empty selected-book snapshots, optionally inspect
   `/events/{id}`: at most 4 extra requests per run and 16 per UTC day, under
   the existing shared/account quotas. Cache metadata receipts for 30 minutes
   and revalidate their fixture binding on reuse. Failures count toward the
   diagnostic budget. Auth, rate-limit and service failures stop further probes.
   Metadata never creates an offer or changes bookmaker selections.
5. Persist the safe diagnostic under the registry attempt and expose it in
   `latest-actionable-coverage-gaps.json` and source previews. No API key or
   authenticated URL is persisted by this diagnostic.
6. Include this input transformation in the forward fingerprint and declare V6.
   Earlier declarations/results remain in history; no past experiment is credited
   as a forward result. The live publication gate remains closed.

## Follow-up: run 43114046507

The intended SHA `2d2c7e4` ran successfully. Summary time: 12 November, 01:45

sporting contexts. Daily collected counts remained 91 lines, 76 contexts and

Selected-book odds returned no event for eight queried NCAA fixtures. The
availability of other bookmakers therefore remains unproven. Unknown-count

field; useful changing count receipts still cache for thirty minutes.

There were also two concrete problems:

- PARI failed with `ConnectTimeout`. Twelve targets were deferred, not recorded
  as confirmed absent. A single connection retry per provider call is now charged
  against the same physical/shared budget and preserves confirmation reserves.
  It never retries auth, plan or rate-limit responses.

  The saved DC Power receipt exposed an overly strict squad-label check:
  `DC Power FC — Brooklyn FC`, while its own league explicitly said
  `USA - USL Super League, Women`. A missing W marker may now be supplied only
  from an explicitly women's competition, with both target squads women.
  Different clubs, youth/reserves, reversed teams, live status, wrong IDs or
  changed kickoffs remain rejected. This is a receipt-local transformation;
  no global club-name alias was introduced. Previously rejected women's attempts
  are retried once under quote identity revision 2.

Full safe returned fixture metadata is now recorded with account-level
diagnostics, so other name mismatches can be examined without depending on
the first two response samples. FAS/Inter and Piratas/La Paz are not automatically
unblocked by this women's-label repair.
