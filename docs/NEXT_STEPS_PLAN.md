# План дальнейших действий

## Цель

Сделать бота менее пустым по выходу, но не ценой резкого ухудшения качества.

## Неделя 1 — инструментирование

- Подключить расширенный `sheet_export.py`.
- Включить `guard_report.py`.
- Собирать CSV/JSON по каждому прогону.
- Проверить, какие 3–5 причин чаще всего убивают публикацию.

**KPI:**
- каждый run имеет полный export;
- по каждому run видны top guard reasons;
- пустые прогоны можно объяснить без Telegram-логов.

## Неделя 2 — мягкая настройка порогов

- Применить `recommended.env` в staging.
- Снизить часть market-derived и simple fallback порогов.
- Не поднимать максимальную ставку.

**KPI:**
- доля пустых прогонов падает минимум на 30–40%;
- не растёт доля ставок с odds выше контролируемого диапазона;
- shadow pool увеличивается.

## Неделя 3 — калибровка вероятностей

- Подключить `ProbabilityCalibrationService`.
- Вести сравнение `raw_prob`, `adjusted_prob`, `market_prob`, `final_prob`.
- Проверить bucket-метрики: 45–50%, 50–55%, 55–60%, 60%+.

**KPI:**
- уменьшается средний gap к рынку;
- Brier score не ухудшается;
- post-calibration rejects становятся осмысленнее.

## Неделя 4 — shadow A/B

- Часть сигналов публиковать, часть держать в shadow.
- Сравнить:
  - старую политику
  - новую env-политику
  - новую env + calibration

**KPI:**
- hit rate и ROI не хуже базовой линии;
- CLV и Brier становятся стабильнее;
- качество объяснимости повышается.

## Неделя 5 — чистка слабых сегментов

- Отдельно разобрать:
  - high odds h2h
  - low-tier leagues
  - spreads с малым числом books
  - totals near 50/50
- Для плохих сегментов добавить сегментные штрафы в calibration-profile.

**KPI:**
- негативные сегменты явно перечислены;
- для них есть либо штраф, либо запрет, либо перенос в shadow-only.

## Неделя 6 — production rollout

- Увеличить `max_picks_per_run` только если качество не просело.
- Оставить аварийные fallback-механики включёнными, но контролируемыми.
- Раз в день строить summary по:
  - published
  - shadow
  - rejected
  - top guards
  - ROI
  - hit rate
  - Brier
  - CLV

## Ежедневный операционный цикл

1. Утро — проверить daily report и top guard reasons.
2. День — посмотреть, какие лиги/рынки системно уходят в reject.
3. Вечер — обновить calibration profile, если накопилась новая статистика.
4. Раз в 3–4 дня — сверить published vs shadow.
5. Раз в неделю — пересматривать только 1–2 группы настроек, не весь `.env` сразу.
